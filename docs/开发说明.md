# lan-video-review 开发说明

面向用户的使用说明见仓库首页的 [README](../README.md)。

局域网内的视频审片批注工具，工作方式类似分秒帧 / Frame.io。视频不上传，始终留在各自的电脑上，全程不需要外网。同事之间还能直接拿共享文件夹里的文件。

**状态：原型（核心流程和拿文件已经在一台 Mac 上用多个实例跑通；Windows 和两台真实电脑之间目前只确认了托盘、互相发现和自动更新）**

## 原型怎么用
- 编译：在 Mac 上运行 `./build.sh`，输出到 `dist/`：
  - `lan-video-review-windows.exe`：Windows 版，没有命令行窗口
  - `局域网审片.app`：Mac 版，Apple 芯片和 Intel 芯片通用，没有窗口和 Dock 图标
  - `lan-video-review-mac.zip`：打包好的 Mac 版，给下载页用。浏览器下载的 .app 会丢掉可执行权限，所以要用 zip。
- 编译需要 Go 和 Xcode 命令行工具：Mac 版的托盘要用 cgo，`build.sh` 会分别为两种芯片编译，最低支持 macOS 13（Go 1.26 起不再支持更早的 macOS）。
- 图标：程序图标、托盘图标和网页的 favicon 都在 `internal/platform/icon.go` 里用代码画出来（蓝底圆角方块、白色对话气泡、播放三角），仓库里没有图片文件。`build.sh` 先运行 `tools/appicon`：Mac 版生成 iconset，再用系统自带的 `iconutil` 转成 `AppIcon.icns` 放进 .app；Windows 版直接生成图标资源 `rsrc_windows_amd64.syso`（16～256 像素共 7 张），编译时 Go 自动把它链接进 .exe，打包完就删掉。整个过程只用标准库和系统自带的工具。
- 托盘图标：Mac 菜单栏用黑色的对话气泡模板图，系统按深浅色菜单栏自动着色；Windows 任务栏可能深也可能浅，所以和程序图标一样画在蓝底圆角方块上（暂停服务时灰底、三角换成两条竖线），16～64 像素共 7 张包成一个 ICO。托盘库 systray 按"大图标"尺寸加载（程序没声明支持高分屏，固定取 32 像素那张），再由系统缩小显示。0.3.0 及之前的版本，Windows 托盘还是旧的"蓝色方块加三角"，没有气泡。
- 运行：双击程序，会自动打开浏览器 `http://localhost:28380`。程序已经在运行时，再次双击只会打开界面。
- 托盘：Mac 在屏幕顶部菜单栏，Windows 在右下角通知区域。菜单里可以打开界面、退出，还有三个开关：开机启动、静默运行、启动服务。这三个开关在网页的"软件配置"里也能改。新版本下载好时，菜单里多一项"更新到 x"。
- 日志：写在配置目录的 `log.txt`（Mac 是 `~/Library/Application Support/lan-video-review`，Windows 是 `%AppData%\lan-video-review`）。
- 分发：把整个 `dist/` 文件夹放在一台电脑上运行，同事用浏览器打开 `http://这台电脑的IP:28380` 就能下载。
- 发布：推送 `v0.3.0` 这样的标签后，GitHub Actions（`.github/workflows/release.yml`）在 Mac 机器上跑测试和 `build.sh`，把 .exe 和 mac.zip 发布到 Release，页面说明取自 `packaging/release-notes.md`。版本号取自标签，写进程序（"软件配置"里和日志里能看到）和 Mac 版的 Info.plist；本机编译时可以用 `VERSION=0.3.0 ./build.sh` 模拟，不给就用 Info.plist 里的。发布时还会用固定证书给 Mac 版签名，并多发布一个签好名的 `update.json` 给自动更新用，要用到仓库 Secrets 里的签名私钥和证书（见"自动更新"）。
- 开发时可以在一台电脑上开多个实例：`go run . -port 53490 -data 某个临时目录 -no-browser -no-tray`。用 `-data` 开的实例不会改动真实的开机启动项。注意它们会通过组播发现这台电脑上正在用的程序并同步批注；不想混进真实数据时，把测试实例的配置设成暂停服务（`config.json` 里写 `"paused": true`），本机网页照常能用。
- 测试：`go test ./...`

## 原型已验证
- 自动发现：两个实例几秒内通过组播互相发现。组播在每张局域网网卡上分别收发，并跳过 VPN、代理软件的虚拟网卡（这台测试机开着代理，有一张 198.18.0.1 的虚拟网卡，已正确跳过）。
- 原片播放：经本机程序转发的视频和原文件逐字节一致，拖进度条走 HTTP 分段读取。
- 帧精度：用画面里编码了帧号的测试视频验证，23.976、24、25、29.97、30、59.94、60fps 下跳到指定帧、逐帧前进、播放后暂停，界面上的帧号都和画面一致。
- 截图：保存的是原片分辨率的当前帧（1280×720 的测试片得到 1280×720 的 PNG）。
- 同步：新建、修改历史、删除都会同步到其他电脑；删除后，带着旧副本重新上线的电脑不会让它复活。
- 权限：别人伪造的修改和删除、签名对不上的记录都会被拒绝；手动篡改硬盘上的记录，几秒内会从同事电脑上恢复原样。
- 安全：本机接口不能从局域网访问，其他网站也不能借用户的浏览器调用本机接口（跨站的修改请求一律拒绝）；`/peer/` 只给程序之间用，浏览器发来的请求一律拒绝，防止恶意网页用 DNS 重绑定读走视频；别人只能取到共享文件夹里扫描到的视频。
- 团队口令：口令不同时看不到对方的视频和批注，界面提示"团队口令不一致"；口令相同后恢复。
- 版本：同名覆盖导出、`(1)`、`_v2` 这类文件会提示"是不是新版本"；确认后旧版本标"文件已不在"，批注保留；可以手动归入或拆出。
- 改名：视频改名为 `LAX43_EP03` 后，文件改成 `LAX43_EP03_v02.mp4`，批注和播放都不受影响，同事那边几秒内看到新名称；目标文件名被占用时跳过并提示；之后导出的 `LAX43_EP03_v03.mp4` 会提示是不是新版本。
- 导出中的文件：模拟一个 20 秒写完的文件，写的过程中不会出现在列表里，写完约 10 秒后出现一次，不会因为中途状态冒出多余的版本。
- Mac 版：通过系统启动 .app 两次，第二次只打开界面，不会重复运行；下载的 zip 解压后可执行权限正常。编译出的程序只依赖系统自带的组件，最低 macOS 13。
- 暂停服务：暂停后局域网请求一律返回"服务已暂停"，不再阻止电脑睡眠，本机网页照常能用并显示提示条；恢复后一切照旧。
- 开机启动：Mac 的启动项文件格式通过系统校验（测试时用临时目录，没有写进真实的启动项）；模拟开机启动并开着"静默运行"时不打开浏览器。
- 退出：从托盘退出后进程结束，没有残留的防睡眠进程。
- 自动更新：在一台 Mac 上用两个实例和本机模拟的 GitHub 测过（用测试密钥）：A 从"GitHub"下载到 0.3.1；B 连不上 GitHub，从 A 那里拿到清单和两个系统的安装包。在 B 的网页上点"立即更新"，约 1 秒后换成 0.3.1（.app 原地替换，没有留下临时文件夹），网页自动刷新。用别的私钥签的"0.3.2"被拒绝，"软件配置"里显示"签名不对"。被改过一个字节的安装包、伪造签名的同事也都被拒绝（`update_test.go`）。
- Mac 固定签名：在临时钥匙串里用自签名证书签两次不同的编译结果，`codesign -v` 通过，designated requirement 完全相同；`build.sh` 按 CI 的方式（临时钥匙串 + 证书）完整跑通，签更新清单的私钥和程序里的公钥对得上。
- 正式发布：v0.3.0、v0.3.1 都由 CI 签名发布，线上的 `update.json` 用内置公钥验签通过、安装包哈希一致，两个版本的 Mac 版 designated requirement 相同。CI 的 macOS 26 上要把临时钥匙串加进搜索列表，codesign 才找得到证书（本机 macOS 27 不用）。
- 真机更新：一台从 GitHub 下载装进"应用程序"的 0.3.0，自己从 GitHub 下载到 0.3.1，点"立即更新"后重启成 0.3.1；系统没有重新询问"本地网络"和"文件与文件夹"授权，桌面上的共享文件夹照常打开，"应用程序"里没有留下临时文件夹。
- Windows 真机更新：一台 Windows 电脑上的 0.3.0 点"立即更新"后重启成 0.3.1（Mac 上的同事列表里显示它的版本变成了 0.3.1）；右下角托盘图标换成了蓝底白色的对话气泡。
- 分享视频：复制出的文字带链接和下载地址；点开后直接打开对应的视频。程序刚启动、还没发现同事时打开链接，会等找到后自动跳过去（约 5 秒）。
- 批注卡片：点内容展开全文和附图，列表刷新后仍保持展开。
- 回复：回复挂在原批注下面，时间码和原批注一样，里面存着被回复的内容；回复别人的回复也挂在最上面那条批注下；写到一半时列表刷新，输入的文字和光标位置都保留；回复可以修改、删除；左侧列表上的数字不算回复。
- 导出：生成的 .html 文件带标题、本地文件名、导出人和时间；表格里有序号、时间码和帧号、合成了画面标注的截图、批注全文和附图、批注人、回复，图片都嵌在文件里（4 条批注约 340KB）。
- 列表和标题显示带版本号的名称（如 `LAX43_EP03_v02`），标题后面灰字是本地文件名。
- 拿文件（一台 Mac 上两个实例，团队口令和正在用的程序不同，互不同步）：
  - 浏览对方共享文件夹，进子文件夹、在不同文件夹里勾选后一起下载；1GB 的文件夹和 4GB 的文件 SHA-256 都和原文件一致，修改时间一致，带上了隔离标记；`.DS_Store` 等隐藏文件没拿，`说明?.txt` 存成 `说明_.txt`；再拿一次存成"大文件 (1).bin"。
  - 下到 1GB 时杀掉对方，显示"正在重试"，对方重启后接着下完；下到 1.7GB 时杀掉自己，重启后接着下完，内容都一致。断点续传、对方文件改过后从头下、重启后续传另有自动测试（`downloads_test.go`）。
  - 用 curl 带着正确口令试 `../`、绝对路径、隐藏文件、批注同步文件夹，都是 404；浏览器发来的请求、不带口令的请求是 403。对方关掉"允许同事下载"后，这边的"文件"按钮几秒内消失，提示"对方关闭了文件下载"。
  - 从 0.3.x 更新上来（配置里没有 `fileShareNotified`）时顶部提示一次，点过后不再出现。
- 共享文件夹整理和备份（一台 Mac 上三个实例 A、B、C，H.264 测试片）：
  - A 用 0.3.x 结构的共享文件夹启动：视频和"素材"文件夹挪进"分享"，"批注同步(别删)"改名为"批注"，`.DS_Store` 留在原地，顶部提示"原有的 2 项已经挪进……需要重新链接素材"。
  - A 写一条批注；B 拿走 A 的整个"分享"，存到"备份/测试A/"，`backups.json` 记着原主人是测试A；B 的"我的视频"是空的，这个视频在测试A 名下，标着本机有备份，批注数 1。
  - 关掉 A 后才启动 C（C 从没见过 A）：C 的列表里出现离线的"测试A"和这个视频，测试B 名下没有多出视频；播放的内容和原片逐字节一致，在浏览器里正常播放、逐帧，看得到 A 的批注，控制栏写着"备份在测试B"。C 在备份上写的批注 `owner` 是 A；重新打开 A 后同步过去，两条批注挂在同一个视频上。
  - 两个实例 A、C，A 在线：C 选中 A 的视频，下面是"备份视频""分享视频""导出批注"（侧栏窄时第三个换行）；点"备份视频"后几秒变成灰色的"已备份"，文件在 C 的"备份/测试A/"里，列表仍然显示 A 的原版。删掉 A 的文件后，C 的列表在 A 名下换成备份版，名字下面是小字"备份版"，控制栏写"测试A 分享（备份版）· 备份在本机"，能正常播放；A 的"分享"里没有被复原。
  - 迁移、备份记录、合并显示、转手备份、"备份视频"从备份者那里拿、原主人删了以后显示备份版（C 从 B 的"备份/A/"拿，原主人仍然是 A）、原主人改名后备份跟着变，另有自动测试（`internal/store/layout_test.go`、`internal/media/backups_test.go`、`backups_test.go`）。

## 原型还没做、还没验证
- 审片流程（看视频、批注同步、权限、改名等）只在一台 Mac 上用多个实例测过，还没在 Windows 电脑上、也没在两台真实电脑之间走一遍；WiFi 下高码率视频是否流畅也没测。
- Windows 的注册表开机启动只编译通过，没有实际运行过。
- Mac 菜单栏里托盘图标的样子没有亲眼确认（这台机器不允许截屏），只确认了托盘菜单能正常工作、日志里没有报错。
- Windows 托盘图标在屏幕缩放 125%、150% 下是否清楚没有专门看过，可能有点糊（见上面"托盘图标"）。
- 只在 Chromium 内核的浏览器里测过，Safari 和 Edge 没测。
- 程序没有正式签名（见"已知问题"）。
- Windows 版 .exe 里的图标资源只在 Mac 上检查过结构（能被 Go 链接、按资源目录读出来的图标完整），还没在 Windows 的资源管理器里亲眼确认。
- 拿文件和备份还没在两台真实电脑之间、也没在 Windows 上走过：Windows 上的 `Zone.Identifier` 标记、资源管理器里"打开文件夹""打开所在文件夹"、Windows 上迁移时文件正被占用的情况，都只编译通过或按文档写的；WiFi 和千兆有线下的实际速度也没测。

## 要解决的问题
团队里 Win 和 Mac 电脑都有，大家需要互相审片、在画面上批注，但不想把视频集中上传，原因是：
- 文件大，上传慢，占空间
- 版本改得快，不想每次都重新上传
- 不希望文件离开本机
- 不想维护 NAS 或服务器

## 已确定的要求
1. 完全离线：断开外网也能用。
2. 轻量：每人下载一个双击即用的便携程序，不用安装；之后的引导和教学都在网页里完成。
3. 身份：设备码加昵称，不接第三方登录。
4. 批注去中心化保存：每个人的共享文件夹里都有一个"批注"文件夹（0.3.x 叫"批注同步(别删)"），存全部批注（JSON）和截图（PNG）。
5. 批注人可以修改或删除自己的批注，修改保留历史，其他人不能修改或删除。
6. 播放和批注都在网页里完成，所有人用同一个播放器；播放原片，不转码、不压缩。
7. 用文件指纹管理版本，不靠文件名。

## 方案

### 程序
- Win 和 Mac 各一个便携程序（Win 是 .exe，Mac 是 .app），双击后在后台运行，并自动用默认浏览器打开 `http://localhost:端口`。
- 程序负责开放共享文件夹里的视频、发现局域网里的其他人、同步批注和签名，网页只负责界面。
- 新人怎么拿到程序：任何一台正在运行程序的电脑都提供一个下载页（`http://对方IP:端口`），里面有 Win 和 Mac 两个版本，以及图文引导。不需要外网。
- 第一次打开时的引导：起昵称 → 选择共享文件夹 → 允许防火墙和本地网络权限 → 演示怎么播放和批注。

### 托盘和后台运行
- 托盘菜单：状态（昵称、运行中或已暂停）、打开界面、三个开关、退出。网页"软件配置"里有同样的三个开关，两边改了互相同步。新版本下载好时，"打开界面"下面多一项"更新到 x"。
- 启动服务：关掉后程序只留在托盘里，不广播、不同步、不扫描，局域网请求一律拒绝，同事那边显示你离线，也不再阻止电脑睡眠。这个状态会保存下来，开着开机启动的话，开机后也是暂停状态。
- 开机启动：Mac 在 `~/Library/LaunchAgents/local.lan-video-review.plist` 放一个启动项，Windows 写在当前用户注册表的"启动"项里，都不需要管理员权限。启动项里记着程序路径，双击打开程序时会顺便更新，程序挪过位置也不会失效。用 `-data` 另开的实例（开发测试用）不会去更新，免得启动项被改成指向测试程序。
- 静默运行：开机启动时不弹出浏览器，只在托盘里待命。只有开着"开机启动"时才能勾选。

### 自动更新
工具更新得频繁，所以程序自己检查新版本、在后台下载，下载好后提示，用户点一下就换上。代码在 `update.go`（流程、接口）和 `internal/update/`（签名、下载、替换程序）。
- 什么时候检查：启动后 5 秒（开机启动和手动打开都算）、恢复服务时、之后每 6 小时查一次 GitHub（失败时 10 分钟后再试，开机时网络可能还没好）；同步时发现同事缓存了更新的版本，马上去要；"软件配置"里可以手动"检查更新"。暂停服务期间不联网检查。`go run` 出来的版本号是 `dev`，不检查。
- 从哪里拿：
  - GitHub：用 Release 的下载地址 `releases/latest/download/update.json`，不走 API，没有访问次数限制。
  - 局域网：每台电脑在 `/peer/info` 里报自己运行的版本（`version`）和缓存里可以给别人的版本（`update`，两个系统的安装包都下载好了才报，免得同事来要时还没下完），0.2.x 会忽略这两个字段，照常互通。看到有更新的，就从对方的 `/peer/update`（清单）和 `/peer/update/文件名`（安装包）下载。只要有一台电脑连得上 GitHub，其他电脑都能从局域网拿到，符合"断开外网也能用"。
  - 先找同事，再找 GitHub；某个来源失败后 10 分钟内不再找它（手动检查不管这个）。
- 怎么防伪：局域网里谁都能说自己有"新版本"，所以发布时 CI 用 Ed25519 私钥给 `update.json` 签名，清单里写着版本号和两个安装包的大小、SHA-256；程序里只有公钥（`internal/update/key.go`）。从谁那里拿到的都要验签、对大小和哈希，只接受比自己新的版本，换上之前再校验一遍缓存里的文件。安装包本来就是公开的，`/peer/update` 不需要团队口令，和其他 `/peer/` 接口一样拒绝浏览器、暂停服务时拒绝。
- 缓存：配置目录下的 `updates/<版本>/`，放验过签名的清单和安装包，只留最新的一个版本，比正在运行的版本旧就删掉。先下本机系统的安装包，下好就提示；再下另一个系统的，这台电脑也就能给用另一个系统的同事中转。没下载全时每分钟看一次，接着下（失败的来源照样 10 分钟内不再找）。正在运行的版本缓存里没有时（比如手动装的最新版），也从同事或 GitHub 把这个版本的清单和两个安装包下下来，只是为了给同事中转，界面上不提示、不显示进度；每台电脑因此多占约 20MB。下载页也优先给缓存里的安装包，新同事从任何一台装了最新版的电脑都能下到。
- 换新版本：只在用户点"立即更新"（网页顶部的提示条、"软件配置"、托盘菜单）时才换，因为程序要重启几秒，正在看你视频的同事会中断。
  - Windows：运行中的 .exe 不能覆盖但能改名。新版本先复制成 `.exe.new`，旧的改名为 `.exe.old`，新的再改成原名；`.old` 下次启动时删掉。路径不变，开机启动项和防火墙规则照样有效；程序自己下载的文件没有"来自网络"的标记，打开时不会弹 SmartScreen。
  - Mac：在 .app 所在的文件夹里用 `ditto` 解压新版本（保留可执行权限和签名），再把新旧两个 .app 换位置，保留用户起的名字；任何一步失败都还原。直接在"下载"里打开、被系统挪到随机位置运行的 .app（路径里有 `AppTranslocation`），或者所在文件夹没有写权限时，不能原地替换，提示条改成说明原因、给出手动下载的链接。
  - 换好后带上内部参数 `-restart` 启动新程序，旧程序退出。新程序抢端口时不把"已有审片程序在运行"当成退出理由，最多等 20 秒旧程序让出端口，等不到就静默退出（旧程序还在）；不打开浏览器。已经打开的网页发现版本号变了会自己刷新，正在写批注或回复时只提示、不打断。
- Mac 的签名：临时签名每次编译都不一样，系统会当成新程序，重新询问本地网络、桌面文件夹等权限，自动更新就谈不上"无感"。所以发布时用一张固定的自签名证书（CN `LanFrame Self-Signed`，2036 年到期）签名，designated requirement 是 `certificate leaf = H"4cc45739…"`，换版本也不变，系统能认出是同一个程序。证书不是 Apple 签发的，第一次下载时"无法验证开发者"的提示照旧；程序自己下载的更新没有隔离标记，不会再拦。本机编译不设 `MAC_SIGN_IDENTITY` 时仍然是临时签名。
- 密钥和证书：存在 GitHub 仓库的 Secrets 里，`UPDATE_SIGNING_KEY`（更新清单的私钥）、`MAC_SIGN_P12`（证书和它的私钥，p12 文件的 base64）、`MAC_SIGN_P12_PASSWORD`；证书的 SHA-1 是公开的，写在 `release.yml` 里。维护者电脑上的备份在 `~/.lanframe-keys/`，请另存一份到密码管理器。
  - 更新私钥丢了：用 `go run ./tools/signupdate -genkey 文件` 生成新的一对，公钥换进 `key.go`，私钥更新到 Secrets。旧版本的程序认不出新密钥签的版本，大家要手动装一次。
  - 证书丢了：重新生成一张，换掉 Secrets 和 `release.yml` 里的 SHA-1。Mac 用户更新后要再允许一次权限。
  - `tools/signupdate` 签完会用程序内置的公钥验一遍，私钥和公钥对不上时报错，CI 不会发布出谁都更新不了的版本。
- 开发测试：环境变量 `LANFRAME_UPDATE_BASE` 把 GitHub 地址换成本机的测试服务（目录结构同 Release：`latest/download/update.json`、`download/v版本/文件名`）；`-ldflags "-X lanreview/internal/update.publicKey=测试公钥"` 换成测试公钥。

### 分享视频链接
- 左侧列表里，当前选中的视频名下面有"备份视频"（只有同事的视频有，见"备份"）、"分享视频"和"导出批注"（只有当前视频显示，侧栏窄时换行）。
- "分享视频"会复制一段文字，可以直接粘贴到飞书、微信。只分享视频（具体到版本），不分享单条批注：
  ```
  剪辑小A 分享了视频「LAX43_EP03_v02」：
  http://localhost:28380/#v=视频指纹&o=分享者
  （需要先打开局域网审片程序。还没装的话，用浏览器打开 http://192.168.1.92:28380 下载）
  ```
- 链接指向对方自己电脑上的程序，打开后直接选中这个视频。视频要能播放，分享者（或者有同一个文件的人）得在线。
- 限制：对方必须开着审片程序；要在普通浏览器里打开，飞书、微信的内置浏览器能用但体验不好；双方要在同一个局域网、团队口令一致。

### 导出批注
- 左侧当前视频名下面的"导出批注"，把当前版本的所有批注导出成一个 .html 文件，文件名如 `LAX43_EP03_v02_批注_20261030-1403.html`。
- 文件里是一张表：序号、时间码和帧号、截图（合成了画面标注）、批注全文和附图、批注人和时间、回复。原批注被删了的回复单独成一行，并带上回复里存着的原批注内容。
- 全部在网页里生成：截图和画面标注在浏览器里合成（中文标注能正常显示），缩到最宽 960 像素的 JPEG 嵌进文件，不需要额外的程序。浏览器打开就能看，也能打印成 PDF。

### 从同事电脑拿文件
用户要的是"主动拿"：打开同事开放的文件，想要什么直接下载，对方不用在电脑前操作。代码在 `files.go`（开放文件）和 `downloads.go`（后台下载和接口）。
- 为什么自己做，不用现成的：
  - AirDrop 只在苹果设备之间，第三方程序最多在 Mac 上弹出 AirDrop 的发送框，不能接收，到不了 Windows（逆向的 OpenDrop、OWL、Owly 只能在 Linux 上用，还挑网卡）。
  - Windows 的"附近共享"只在 Windows 之间，也没有给第三方程序的接口。这两个都只能推送，做不到主动拿。
  - 系统自带的 SMB 文件共享能跨平台主动拿，但要设账号密码、开防火墙，Windows 11 默认还禁了来宾访问，普通同事配不起来。
  - [LocalSend](https://github.com/localsend/protocol) 主要是推送，协议要 HTTPS 自签证书（手机端现在还要求客户端证书）、另一个端口和组播地址。以后要和手机互传再考虑兼容。
  - 程序本来就是"拉"的模式（看视频就是读对方的原片），发现、团队口令、程序间通道都是现成的，扩展成开放文件最省事。
- 开放什么：共享文件夹里的所有文件和子文件夹（"分享""备份"，以及没挪走、放在根目录的），只读。不列出、也拿不到：以 `.` 或 `~$` 开头的、`Thumbs.db`、`desktop.ini`、`$RECYCLE.BIN`、`System Volume Information`、顶层的批注文件夹（新旧名字都算）、符号链接。"软件配置"里可以关掉（`noFileShare`），关掉后同事仍然能看视频。
- 接口（都在 `/peer/` 下，所以和其他程序间接口一样拒绝浏览器、暂停服务时拒绝，另外要团队口令）：
  - `GET /peer/files?path=相对路径`：列出一层；加 `&deep=1` 把选中的文件夹展开成文件清单（最多 5 万个），选中的是文件时就是它自己。
  - `GET /peer/file?path=相对路径`：用 `http.ServeContent` 返回文件，支持 Range 和 If-Range。
  - 路径用 `/` 分隔，一段一段检查（不能是空的、`.`、`..`、隐藏的名字；Windows 上不能有 `\` 和 `:`），再用 Go 的 `os.Root` 打开共享文件夹，跳出共享文件夹（包括符号链接指出去）一律打不开。
  - 关了文件下载返回 403，共享文件夹打不开返回 503，文件不在了返回 404。`/peer/info` 里带 `files`（0.3.x 没有这个字段），同事那边据此显示"文件"按钮。
- 本机网页用的接口：`GET /api/peer-files`（网页不能直接访问 `/peer/`，由程序代为去要）、`POST /api/downloads`、`POST /api/downloads/{id}/cancel|retry|reveal|delete`、`POST /api/downloads/clear`、`POST /api/downloads/open`（打开"备份"）、`POST /api/open-share`（打开"分享"）；下载列表放在 `/api/state` 的 `downloads` 里，不另开轮询。
- 下载（`downloads.go`）：
  - 选中的每一项是一个下载任务。开始前先把文件夹展开成文件清单，算好本机路径（见下面"存在哪"）：本地已经有大小和修改时间都一样的文件（差 2 秒以内，有的磁盘只记到 2 秒）就算已经下完；同名但不一样的（或者别的没下完的任务占着）叫"名字 (1)"，不覆盖；再拿一次同一个文件夹，等于把备份补全。剩余空间不够直接提示。
  - 文件名一段一段清理成 Win 和 Mac 都能用的：`\ / : * ? " < > |` 和控制字符换成 `_`，去掉结尾的句点和空格，`CON`、`NUL`、`COM1` 这类前面加 `_`；最后再确认路径在下载文件夹里面。
  - 同时最多下 2 个文件。每次都按设备 ID 找对方当前的地址，对方换了 IP 也不影响；对方离线就停在"等对方上线"，上线后自动接着下；本机暂停服务时也停下。
  - 先写到 `名字.lanpart`，续传时带 `Range: bytes=已下大小-` 和 `If-Range: 对方的修改时间`：对方的文件没改过返回 206 接着下，改过了返回 200 从头下；已经下全了返回 416，直接改名。30 秒没收到数据就断开重试，间隔从 5 秒翻倍到 1 分钟，连续失败 10 次（这次有收到数据就不算）才记为失败，等用户点"重试"。
  - 下完核对大小、改回原名，用 `os.Chtimes` 设成对方的修改时间（剪辑软件按修改时间认素材），再加上"来自其他电脑"的标记：Mac 写 `com.apple.quarantine`，Windows 写 `:Zone.Identifier`（ZoneId=3），和浏览器、AirDrop 一样，收到的程序第一次打开时系统会检查。
  - 不校验整个文件的哈希：对方要把整个文件读一遍，大视频太慢。靠 TCP、大小核对和 If-Range。
  - 下载列表存在配置目录的 `downloads.json`，只在状态变化时写；程序重启或自动更新后，从 `.lanpart` 接着下。取消时删掉 `.lanpart`，已经下完的文件保留。
  - 删除（`deleteDownload`）：只能删已经结束的任务。下好的文件移到废纸篓（Mac 用 `NSFileManager trashItemAtURL`，要 cgo；Windows 用 `SHFileOperationW` 加 `FOF_ALLOWUNDO`，太大放不进回收站时系统会先问），能在访达里"放回原处"、在回收站里还原；`.lanpart` 直接删。文件夹任务的文件夹里只有这项任务的文件（不算隐藏文件）时整个文件夹移走，否则只移走这项任务的文件，再删掉空下来的子文件夹。每个路径都先确认在"备份"里面。删完从列表里拿掉，重新扫描一次，备份的视频马上从列表里消失。测试里把 `trashPath` 换掉，不往真的废纸篓里放东西。
  - 本机的问题（没权限、磁盘满了）和对方的问题（团队口令不一致、关了文件下载）让整个任务停下，等用户处理后点"重试"；对方删了的文件只记这一个失败。
- 存在哪：自己共享文件夹的"备份/来源/剩下的路径"（`backupPath`）。对方"分享"里的，来源是对方的昵称，去掉"分享"这一层；对方"备份/X/"里的（转手的备份），来源沿用 X；对方放在根目录的，来源也是对方的昵称。每一段都用 `safeName` 清理。程序本来就有共享文件夹的访问权限，Mac 不用再允许访问"下载"文件夹。最早的设计是存到系统"下载"文件夹、可以在设置里换，改成备份以后去掉了。
- 界面：左边在线、开放了文件、口令一致的同事标题行有"文件"；文件窗口里点文件夹名字进入，勾选框和文件名是勾选，不同文件夹里勾的一起算；左边列表底部有下载记录时显示一行（"下载中 N 项"、"N 项没下载成功"或"下载记录"），点开是下载列表；下载完在顶部提示一次，带"打开所在文件夹"（Mac 用 `open -R`，Windows 用 `explorer /select,`，只接受下载列表里记着的路径）。
- 从 0.3.x 更新上来的用户，配置里没有 `fileShareNotified`，第一次打开时顶部提示一次：共享文件夹分成了三个子文件夹、整理的结果（配置里的 `layoutNote`，比如挪了几项、需要重新链接素材）、共享文件夹里的文件同事都能下载。新设置的用户在设置页上已经看到说明，直接记为提示过。

### 共享文件夹的结构（0.4.0 起）
- 共享文件夹里有三个子文件夹（`internal/store/layout.go`）：
  - "分享"：自己要给同事看的视频和文件。
  - "备份"：从同事那里拿来的东西，按来源分子文件夹（见"从同事电脑拿文件"）。
  - "批注"：批注记录、截图、`versions.json`、`backups.json`。0.3.x 叫"批注同步(别删)"。
- "分享"只是放东西的约定：扫描视频、给同事浏览文件时仍然看整个共享文件夹（跳过根目录下的批注文件夹和隐藏文件），没挪成的、以后误放在根目录的照样能分享，不会突然断。批注文件夹只认根目录下的，别处叫"批注"的是用户自己的文件夹。
- 整理（`store.PrepareShare`，打开共享文件夹时先做）：建好"分享"和"备份"；从旧结构更新上来（有"批注同步(别删)"），或者用户在设置里换了共享文件夹并确认过时，把根目录下的其他东西 `os.Rename` 进"分享"（同一块磁盘里改名，很快，不复制）。
  - 不挪：隐藏文件、`~$` 开头的、我们自己的三个文件夹、旧的批注文件夹。用户自己恰好叫"批注"的文件夹（里面没有 `records/`）当普通文件夹挪走；旧结构里还没有程序的"备份"，叫"备份"的也是用户自己的，同样挪进"分享"，挪完再建程序的"备份"。用户原来就有的"分享"直接当成程序的。"分享"里已经有同名的，叫"名字 (1)"。
  - 共享文件夹是个人文件夹、桌面、文稿、下载、影片、视频、图片、音乐（包括被 OneDrive 接管的）或者整个磁盘时不挪，免得把整个桌面挪走。
  - 都挪完以后才把"批注同步(别删)"改名为"批注"；有一项没挪成（比如 Windows 上文件正被占用）就保留旧名字，下次打开时再试，旧名字照常能用。
  - 设置页上换共享文件夹时，`/api/fs` 返回会挪动的项数（`movable`），网页先确认"原有的 N 项会挪进'分享'，剪辑软件工程里会显示素材离线"。
- 挪动会让剪辑软件工程里的素材离线，这是用户确认过的取舍：结构整齐，更新时提示一次怎么重新链接；批注按指纹对应，不受影响。

### 备份
拿来的视频是原主人视频的备份：原主人不在时同事也能从这里看，批注是同一套，不算一个新视频。代码在 `backups.go` 和 `internal/media/backups.go`。
- 为什么天然可行：视频按指纹识别（大小加上开头、中间、结尾各 4MB 的 SHA-256），批注只按指纹查；下载是逐字节复制，指纹不变，不转码；播放时（`apiStream`）先读本机，再找任何在线、列表里有这个指纹的同事。
- 记录：`批注/backups.json`，指纹 → 原主人的设备 ID、昵称，以及下载时原主人列表里这一项（名称、视频名称、版本组、版本号）。只在自己电脑上，不参与同步。
  - 一个文件下完、改回原名之前记（`noteBackup`），免得扫描先把它当成自己的新视频：扩展名是视频的，用 `.lanpart` 算指纹，在来源同事的列表里找；那一项本身是备份的，原主人沿用它的原主人（转手）。原主人是自己、或者自己本来就有这个视频的，不记。
  - 同步到原主人时（`syncPeer`）用他最新的列表刷新，原主人改了名、多了版本，备份跟着变。
- 列表（`listing`）：扫描到的视频按指纹分成自己的和备份。自己的照常进版本组、生成列表项；备份不进自己的版本组，不会问"是不是新版本"，按记录生成列表项，带上 `origin`、`originName`。这就是发给同事的 `/peer/videos`；0.3.x 不认这两个字段，会当成拿的人自己的视频，照样能播、批注照样对得上。
- 显示（`videoView`，只给本机网页的 `/api/state`）：所有备份（自己的和同事的）归到原主人名下，在线的备份者记在 `holders` 里（自己是"本机"，另外标 `local`）。
  - 优先显示原主人的文件（原主人在线，或者这次运行里见过、他的列表里文件还在）。原主人离线时照样从备份播放，列表上不另外标。
  - 原主人那边已经删了（他的列表里标"文件已不在"），或者原主人列表里没有、这次运行里从没见过原主人（按记录里的昵称补一个离线的同事），显示备份版（`backup`）：网页上文件名下面是小字"备份版"，控制栏写"xx 分享（备份版）"。不替原主人复原文件。
  - `/peer/videos` 和播放仍然用原始列表。
- "备份视频"（`startVideoBackup`，`POST /api/backup`）：选中同事的视频时名字下面的按钮，只备份这一个视频，不用进"文件"里找。
  - 按指纹拿（`/peer/video/{指纹}`，本来就给播放用，支持 Range）：下载任务记着指纹（`fp`），每次重试都重新挑来源，原主人在线、文件还在就找他，不然找在线的、列表里有这个指纹的同事（`downloadSource`）。某一台说没有了（404）只算一次失败，换一台再试。
  - 存到"备份/原主人/…"，路径照原主人那边的（去掉"分享"这一层）。名称和位置取原主人列表里的，原主人不在时取备份者列表里记的。
  - 自己的视频、谁都没有文件了的（"文件已不在"）没有这个按钮；备份版也能再备份一份（从别的备份者那里拿）。本机已经有了显示"已备份"，正在备份显示"备份中…"，同一个视频不会重复建任务。
- 在备份上写的批注，视频的主人（`owner`）仍然是原主人。
- 收不回来：有人备份过以后，原主人删掉自己的文件，别人仍然能从备份看到。和批注删除一样，写在 README 的常见问题里。

### 身份
- 第一次运行时生成一对 Ed25519 密钥。私钥存在本机的用户配置目录里（Mac 是 `~/Library/Application Support/lan-video-review`，Windows 是 `%AppData%\lan-video-review`），不放进共享文件夹；公钥的短指纹作为设备码显示。
- 批注 ID 的前半段是作者公钥的哈希，所以即使原始记录已经被删掉，也能验证"删除"确实来自作者本人。
- 每条批注、每次修改、每次删除都用私钥签名。其他人同步时会验证签名，伪造或被篡改的记录直接忽略。
- 不提供导出、导入：换电脑就是新身份，旧电脑上写的批注在新电脑上改不了、删不了（仍然能看到）。以前的身份文件导出、导入已经去掉。

### 发现和连接
- 参考 LocalSend：程序在局域网里用组播广播"我在这里"，其他程序收到后回应；组播被屏蔽时，挨个询问本网段的地址；还可以手动输入 IP（跨网段、访客 WiFi 隔离等情况）。
- 组播在每张有内网地址的网卡上分别发送，跳过 VPN 和代理软件的虚拟网卡，否则开着代理时广播可能只发进虚拟网卡。
- 第一次运行时需要允许 Windows 防火墙和 macOS 的"本地网络"权限。
- 端口：网页和接口用 TCP 28380，组播用 UDP 28381。不能放在 49152 以上：Mac 和 Windows 会从那一段随机挑端口给对外连接用。最早用的 53380 就被代理软件 FlClash 的一个连接占过，导致双击程序没反应。
- 端口被占用时先重试 5 秒，还不行就弹出错误提示框再退出（占着端口的如果是已经在运行的审片程序，就只打开界面）。程序没有窗口，不弹框的话用户只会觉得"双击没反应"。
- 团队口令（可选）：设置后，别人必须带着相同口令才能取你的视频列表、视频和批注。请求里只带口令的哈希，不带原文。下载页不受口令限制。

### 批注存储与同步
- 文件夹结构：
  - `批注/records/<记录ID>.json`：一条记录一个文件。记录类型有：新建批注、修改批注、删除批注。
  - `批注/images/<哈希>.png`：截图和附图，按内容哈希命名，相同的图片只存一份。
- 一条批注包括：视频指纹、帧号、时间码、文字、画笔标记（存成矢量数据，可以重新绘制）、当前帧截图、附图。
- 同步方式：两台电脑连上时对比记录清单，互相补齐缺少的文件。记录只会增加，删除批注也是新增一条"删除"记录，所以永远不会冲突；有人手动误删了文件，下次同步时会自动补回来。
- 两个人从没同时在线时，靠第三个在线的人中转，因为每个人都带着全部批注。
- 校验不通过的记录（签名不对，或者是更新的版本才有的记录类型）会被拒绝，并且 10 分钟内不再从同一台电脑下载，免得每轮同步都重新下载、写日志。
- 扫描视频时跳过这个文件夹。

### 批注规则
- 排序：批注栏标题右边的下拉菜单，可选"按时间码"（默认）、"按批注时间（最新在前）"、"按批注时间（最早在前）"。回复始终按时间先后挂在原批注下面；导出的表格始终按时间码排。选过的排序方式这台电脑的浏览器会记住。
- 批注列表是左图右文的卡片：顶部左边是批注人，右边是批注时间（改过的批注在这一行标"已修改"，点开看历史）；下面左边是截图缩略图（竖屏素材限制高度），右边从上到下是批注内容、时间码、按钮（靠右对齐）。
  - 内容收起时最多显示三行，超出的部分省略；附图只显示成"[图片]"；时间码和按钮跟在内容后面（试过固定在卡片底部，不好看）。
  - 点批注内容展开，显示全文和附图（连同回复里的），再点一次收起。点缩略图、时间码或卡片其他地方会跳到那一帧并显示画面标注。
  - 按钮：批注人有"修改""删除""回复"，其他人只有"回复"。不是本人的批注和回复，页面上不显示"修改""删除"；程序也会校验，绕过页面也改不了、删不了别人的。
- 回复：点"回复"写回复，Ctrl+Enter（Mac 上 Cmd+Enter）发送，可以加图片、粘贴截图。回复和回复框都在卡片右栏、原批注下面，和批注文字左对齐，不从截图下面开始。
  - 回复是一条独立的批注记录，时间码和原批注一样，不截图、不画画面标注；里面带着被回复的内容（作者和文字），页面上不显示，导出时、原批注被删后用得上。
  - 回复别人的回复，也挂在最上面那条批注下面。自己的回复可以修改、删除。
  - 每条回复：左边是回复人，右边是时间；按钮靠右；回复之间用虚线隔开。
  - 原批注被删了，回复归到一张"原批注已被作者删除"的卡片里。
- 没有"完成"功能：试用后觉得意义不大，已经去掉。左侧视频列表上的红色数字是这个视频的批注数（不算回复）。
- 视频名称：左侧列表和播放器控制栏都显示带版本号的名称（如 `LAX43_EP03_v02`），控制栏里名称下面的灰字是本地文件名。没起名的视频，文件名里已经带版本号就照用，没带才补上 `_v01` 这样的后缀。
- 修改：只有批注人可以改。每次修改都是一条新记录，界面显示最新版本，可以查看历史。
- 删除：只有批注人可以删。点"删除"会弹出程序自己的确认窗口（显示要删的内容），点"删除"才真的删，点"取消"或窗口外面都不删。
  - 删除时新增一条带签名的"删除"记录。各台电脑同步到这条记录后，会把这条批注的所有版本和它用到的图片（没有被其他批注用到的）从自己硬盘上清掉，只留下这条很小的删除记录。图片会在 10 分钟后才清理，给刚上传、还没发布的图片留出时间。
  - 删除记录要永久保留：否则一台离线很久的电脑带着旧批注回来同步时，这条批注会"复活"。
  - 列表里留一行灰色的"作者已删除这条批注"，不显示内容，免得剪辑师找不到之前看过的意见。
  - 删除不能保证彻底消失：之后再也不上线的电脑，或者有人提前复制过文件夹，都还会留着。

### 播放
- 播放器只有视频下方一行控制栏（原来视频上方的标题栏已经合并进来，视频能多占一些高度）：
  - 左边：带版本号的名称，自己的视频后面跟着"改名""调整版本"（空间不够时换到下一行）；下面一行灰字是本地文件名、分享者、大小、版本数。
  - 中间：时间码，下面一行灰字是帧号、分辨率、帧率、编码。
  - 右边："播放"和"批注这一帧"。
  - 没有上一帧、下一帧按钮，逐帧用键盘 ← →，按住 Shift 一次 10 帧。
- "这个文件是不是 xx 的新版本？"的提示只在需要分享者确认时出现在视频上方。
- 观看者的浏览器通过本机程序读取分享者电脑上的原文件（HTTP 分段读取），由浏览器直接解码播放，画质和原片一样。截图取当前帧，存成无损 PNG。
- 帧精度：程序读取 MP4 内部的帧表，得到准确的帧率和每一帧的时间；网页用 requestVideoFrameCallback 对齐到具体帧。遇到可变帧率的素材时给出提示。
- 只能播放浏览器能解码的格式：H.264 最稳；H.265 取决于显卡和浏览器版本；ProRes 和 4:2:2 10bit 的 H.264 放不了。放不了时明确提示，不做转码。
- 不压缩就没有"网速慢自动降清晰度"，网速不够时只会缓冲。有线网络没问题，WiFi 下的高码率 4K 需要实测。
- 不同系统和浏览器对视频色彩（尤其是 gamma）的处理不一样，严格审色彩时浏览器不能当标准参考。
- 时间码一律从 00:00:00:00 开始、按非丢帧计算，不读视频自带的起始时间码。剪辑软件里时间线从 01:00:00:00 开始（DaVinci Resolve 的默认设置），或者用 29.97 丢帧时间码时，批注的时间码会和剪辑软件对不上，但帧号是准的。

### 版本管理
- 快速指纹：文件大小 + 开头、中间、结尾各取若干 MB 算 SHA-256，几乎瞬间算完。
- 指纹相同就是同一个文件：文件改名或移动后，批注会自动跟着走；两个人有同一个文件时，主人离线也能从另一个人那里播放。
- 新文件的名字去掉版本标记后（`v2`、`第2版`、`(1)`、`final`、`副本` 等）和已有视频相同时，提示分享者"这是不是 xx 的新版本"，确认后归入同一个版本组。`shot01`、`shot02` 这种镜头号不算同一个片子。
- 分享者可以手动把视频归到别的视频下面，或者拆出来单独成一个视频。
- 版本号按文件修改时间排，显示为 v01、v02。每个版本的批注各自独立；旧版本文件不在了但还有批注时，列表里保留它，标"文件已不在"，只能看批注和截图。
- 同一位置的文件被覆盖、而旧文件没有批注时，新文件直接顶替，不提示；旧文件有批注才问"是不是新版本"。
- 正在导出或拷贝的文件先不算进来：修改时间在一分钟内的文件，要连续两次扫描（每 5 秒一次）大小和修改时间都不变、并且 10 秒内没再改动，才算写完。
- 视频名称：分享者可以给视频（整个版本组）起名称，比如 `LAX43_EP03`，同事看到的就是这个名称。可以选择同时把本机文件改名为"名称_v版本号"，比如 `LAX43_EP03_v02.mp4`，扩展名不变，已经不在的版本跳过。改名时会提醒：如果文件被剪辑软件的工程引用，工程里会显示素材离线。
- 版本组只记在分享者自己的电脑上（`批注/versions.json`，不参与同步），随视频列表发给同事。备份不进版本组，版本照原主人的（见"备份"）。

## 已知问题
- 分享者的电脑关机或睡眠，他的视频就播不了（有同事备份过、并且在线时从备份播放），但批注和截图仍然能看。分享期间程序会阻止电脑睡眠。
- 程序没有签名：
  - Mac 会提示"无法验证开发者"，要去"系统设置 → 隐私与安全性"里点"仍要打开"。
  - Windows 会弹出 SmartScreen 提示，要点"更多信息 → 仍要运行"。
  - 这两步已经写在下载页里。正式签名需要 Apple 开发者账号（每年 99 美元）和 Windows 代码签名证书。
- Mac 访问桌面、文稿、下载里的共享文件夹需要用户允许。系统按程序的签名来记"允许"：0.3.0 起发布版用固定的自签名证书签名，自动更新后不用重新允许（0.3.0 → 0.3.1 实测）；0.2.x 和本机临时签名的编译，每次更新都要重新允许一次。打不开共享文件夹时，界面顶部会说明原因和操作步骤，有"重试"按钮，后台每 15 秒也会自动重试，允许后不用重启。把共享文件夹放在这三个位置以外（比如个人文件夹下新建一个），就不会被询问。
- 共享文件夹不存在时（被移动、删除，或者移动硬盘没接上），程序不会替你重新建一个，而是提示重新选择；文件夹回来后自动恢复。
- 保密：观看时视频数据还是会传到观看者的电脑上，防不住录屏。能做的有：只开放共享文件夹并防止路径穿越；设置团队口令；不想让同事下载共享文件夹里的文件可以在"软件配置"里关掉。局域网里走的是明文 HTTP，同一网段的人理论上能截获视频和拿的文件。

## 可参考的项目
- [FreeFrame](https://github.com/Techiebutler/freeframe)（MIT）：开源的 Frame.io 替代品，支持帧精确批注、画笔、审批流程，能导出 DaVinci、Final Cut、Premiere 的标记点。要先上传、再转码，架构用不了，但界面交互、数据结构和导出格式可以照着做。
- [Clapshot](https://github.com/elonen/clapshot)（GPLv2）：自建的审片工具，支持按时间码评论、画笔、逐帧播放、多人同步播放。同样要上传、转码。GPL 许可证不能直接抄代码。
- [LocalSend](https://github.com/localsend/protocol)：离线的局域网文件互传工具，用组播发现设备，失败时退回挨个扫描地址。发现设备的部分直接参考；文件互传是推送模式，这里要的是主动拿，没有兼容它的协议（见"从同事电脑拿文件"）。

## 实现
用 Go 写成单个可执行文件。除了托盘用的 `fyne.io/systray`（以及它带的 `golang.org/x/sys`）以外只用标准库，依赖都编进程序里，用户不需要另外安装任何东西。网页界面打包在程序里，用原生 JS 写，不需要构建。批注不用数据库，直接读写文件夹。
```
lan-video-review/
├── main.go          启动、写日志、自动打开浏览器、显示托盘；程序已经在运行时，再次双击只打开界面
├── app.go           配置、共享文件夹、暂停服务、开机启动开关、视频改名
├── peers.go         发现其他电脑、同步批注、团队口令
├── files.go         把共享文件夹里的文件开放给同事浏览和下载（只读）
├── downloads.go     从同事那里拿文件：后台下载到"备份"、断点续传、下载列表和接口
├── backups.go       拿来的视频记成原主人视频的备份，网页上归到原主人名下
├── update.go        自动更新：检查和下载新版本、换上后重启，把缓存的新版本给同事
├── server.go        给局域网（/peer/）和本机网页（/api/）用的接口，以及同事看到的下载页
├── tray.go          托盘菜单
├── internal/
│   ├── store/       批注数据：签名的批注记录（每条一个文件）、设备身份；共享文件夹的三个子文件夹和整理
│   ├── media/       视频：扫描共享文件夹、算指纹、读取 MP4 帧表、版本组和改名、备份记录
│   ├── platform/    和操作系统打交道的部分，按系统分成 _darwin、_windows、_other 三份：
│   │                开机启动、防睡眠、错误弹窗、Mac 上转到后台运行、托盘图标和程序图标、
│   │                下载文件夹的位置、剩余空间、"来自其他电脑"的标记、在访达或资源管理器里显示
│   └── update/      自动更新：验证更新清单的签名、下载和校验安装包、替换正在运行的程序（按系统分开）
├── tools/appicon/   打包时生成 Mac 的 iconset 和 Windows 的图标资源
├── tools/signupdate/  发布时给安装包生成签好名的更新清单；也能生成新的签名密钥
├── web/             网页界面（原生 JS，打包进程序）
├── packaging/       Mac .app 的 Info.plist，Release 页面的说明
├── docs/            开发说明（本文件）
├── .github/workflows/release.yml  推送版本标签时编译并发布 Release
├── build.sh         编译 Windows 版和 Mac 版到 dist/
└── dist/            编译结果，不进版本管理
```
- 依赖方向：根目录的程序用四个子包；`media` 用 `store`（同步文件夹名、写文件的工具函数）；`platform` 和 `update` 不依赖其他包。
- 测试跟着各自的包：`go test ./...` 会跑全部。
